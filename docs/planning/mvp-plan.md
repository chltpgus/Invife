# Invife MVP 최종 기획안

> Invife (인바이프): invite + life. "Invite to life"

무료 모바일 청첩장을 6주 만에 출시하는 계획이에요. 기능을 늘리지 않고, 하객이 미감에서 즐거움을 느끼고 결혼식 정보를 쉽게 찾는 데 집중해요.

## 1. 핵심 방향

**한 줄 요약:** 누가 만들어도 잡지 화보처럼 예쁘게 나오는 무료 청첩장이에요. 하객 화면에는 광고가 없어요.

하객이 청첩장에서 중요하게 보는 건 두 가지예요. 청첩장이 얼마나 예쁜지, 그리고 결혼식 정보가 잘 전달되는지예요. 그래서 즐거움은 퀴즈 같은 기능을 더해서가 아니라 디자인에서 주기로 했어요. 처음에는 청첩장 하나로 시작하고, 돌잔치나 생일파티 같은 다른 행사는 출시 후 같은 틀에서 문구와 색만 바꿔 확장해요.

## 2. MVP 범위

| 항목 | 결정 |
|---|---|
| 템플릿 | 청첩장 1종, 색 테마 3개 (추가는 출시 후) |
| 사진 | 최대 10장, 얼굴 위치 지정과 색감 필터 |
| 연출 | 봉투 오프닝, 스크롤 등장 효과 |
| 로그인 | 카카오 로그인과 비회원 작성 |
| 하객 관리 | 받는 사람별 링크(선택), 미응답자 목록, 인원 합계 |
| 공유 | 카카오 공유 SDK, 링크 복사, 공용 초대장 링크·공용 RSVP 링크(분리) |
| 결제 | 없음 (당분간 무료) |
| 광고 | 만드는 사람 화면에만, 5주차에 자리·켜고 끄기(꺼둠), 출시 시 꺼둠 |

## 3. 디자인과 미감

| 항목 | 내용 |
|---|---|
| 톤 | 잡지 화보 같은 에디토리얼, 여백을 넉넉히 둠 |
| 배경과 색 | 종이 느낌 배경에 포인트 색 하나, 검수한 팔레트에서만 선택 |
| 폰트 | 제목용 명조와 본문용 고딕 한 쌍으로 고정 |
| 시각 중심 | 날짜를 05.15처럼 크게 조판 |
| 장식 | 꽃, 리본 같은 클립아트는 쓰지 않음 |
| 바꿀 수 있는 것 | 색 테마, 사진, 문구만 (폰트와 레이아웃은 고정) |
| 화면 모드 | 라이트 색으로 고정해요 |

### 미감을 올리는 장치

1. **사진 크롭과 초점**: 얼굴 위치를 탭해 두면 어떤 화면 비율에서도 얼굴이 잘리지 않아요.
2. **색감 통일**: 원본, 따뜻하게, 흑백 필터 중 하나로 10장의 톤을 맞춰요.
3. **봉투에서 커버로**: 봉투가 열리면 안의 커버 사진이 끊김 없이 화면을 채워요. 2초 이내이고 건너뛸 수 있어요. 봉투는 탭이나 위로 스와이프만 받아요. 옆으로 밀면 카톡 뒤로가기와 충돌하기 때문이에요.
4. **스크롤 등장**: 섹션이 살짝 페이드되며 올라오고 한 번만 재생돼요.
5. **흐린 미리보기**: 사진이 뜨기 전에 흐린 미리보기와 자리를 먼저 잡아 화면이 튀지 않아요.
6. **카톡 미리보기 이미지**: 하객의 첫 접점이라 초대장과 같은 톤으로 디자인해요.
7. **한글 줄바꿈**: 단어 단위로 끊고 제목 줄 길이를 맞춰요.
8. **모션 줄이기**: 기기에서 모션 줄이기를 켜면 봉투 오프닝과 스크롤 등장을 생략해요.

### 넣지 않는 것

동영상 배경, 계속 날리는 꽃가루, 배경음악 자동 재생, 3D, 화면을 가로채는 스크롤 효과, 템플릿마다 다른 모션은 넣지 않아요. 커플 퀴즈도 하지 않아요.

## 4. 초대장 정보 구성

1. 커버: 사진, 이름, 날짜와 시간, 예식장 이름 (스크롤 없이 첫 화면에)
2. 짧은 인사말
3. 양가 혼주 성함: 부모님마다 고인 여부와 표기 방식(예: 故/고)을 따로 고를 수 있어요
4. 연락하기: 신랑, 신부, 혼주에게 전화와 문자 (고인으로 표기한 분에게는 버튼을 보여주지 않아요)
5. 일시 상세와 달력
6. 갤러리: 10장, 탭하면 전체 화면으로 넘겨 보기
7. 오시는 길: 주소 복사, 지도 앱 열기, 주차와 대중교통
8. 마음 전하실 곳: 신랑측과 신부측 계좌를 접어 두고 복사
9. 참석 여부 (RSVP): 참석 여부와 동행 인원(최대 10명)만 받아요 (식사 여부는 받지 않아요). RSVP 마감 기본값은 예식 전날 23:59예요. 마감 없음은 허용하지 않아요. 하객은 마감 전까지 응답을 수정할 수 있어요

스크롤을 내리면 하단에 오시는 길, 마음 전하실 곳, 참석 여부로 바로 가는 작은 바가 나타나요. 봉투 연출은 처음 열 때만 나오고, 다시 열면 바로 커버가 떠요. 정보 섹션에는 모션을 넣지 않아요.

## 5. 로그인과 하객 관리

- **카카오 로그인**: 발행하려면 로그인이 필요해요. 네이버는 출시 후, 애플은 넣지 않아요.
- **비회원 작성**: Supabase 익명 로그인으로 만들기를 시작하고, 발행할 때 카카오 계정을 연결(linkIdentity)해요. 작성 중 이미 가입된 카카오 계정으로 로그인하면, 이 초안을 그 계정으로 옮길지 물어봐요.
- **발행 필수 항목**: 신랑·신부 이름, 날짜, 시간, 예식장, 주소, 대표 사진 1장이에요.
- **공용 링크**: **공용 초대장 링크**와 **공용 RSVP 링크**는 서로 다른 링크예요. 호스트가 받는 사람 명단을 만들지 않아도 공용 초대장 링크로 초대할 수 있고, 공용 RSVP 링크로 이름을 직접 입력해 응답할 수 있어요. 집계는 따로 보여요. 명단과 받는 사람별 링크는 선택 사항이에요.
- **받는 사람 입력** (선택): 이름을 하나씩 입력하거나 목록으로 붙여넣어요. 카카오 친구 목록 연동은 하지 않아요.
- **받는 사람별 링크** (선택): 각 줄에 카톡 공유 버튼과 링크 복사 버튼이 있어요. 초대장 화면에는 받는 사람 이름을 옵션 없이 항상 띄우지 않아요. 링크로 들어온 RSVP에서는 이름 칸을 자동으로 채우고, 링크가 다른 사람에게 다시 공유됐을 때를 위해 「OO님이 아니신가요?」로 이름을 고칠 수 있어요.
- **RSVP**: 참석 여부와 동행 인원(최대 10명)을 받아요. RSVP 마감 기본값은 예식 전날 23:59이고, 마감 없음은 허용하지 않아요. 호스트가 마감일을 바꿀 수 있고, 하객은 마감 전까지 응답을 수정할 수 있어요.
- **호스트 화면**: 응답하지 않은 사람 목록과 참석·동행 인원 합계를 보여줘요.
- **발행 후 수정**: 공유한 뒤에도 시간, 장소, 계좌를 고칠 수 있고 링크는 그대로 유지해요. 발행 취소와 삭제도 할 수 있어요.

## 6. 광고와 수익

- **하객 화면**: 광고를 넣지 않아요. 하객 페이지(`/i/*`)에는 CSP로 광고 스크립트가 들어가지 못하게 막아요.
- **만드는 사람 화면**: 어드민이 아니면 화면당 배너 하나를 보여줘요. 내 초대장 목록, 템플릿 선택, 발행 완료 화면에만 넣어요.
- **광고를 넣지 않는 곳**: 편집 중인 화면, 미리보기, 공유 버튼 근처, 로그인, 하객 명단과 계좌번호가 보이는 화면
- **어드민 구분**: 사용자가 직접 바꿀 수 없는 계정 역할 값으로 판단해 광고를 아예 띄우지 않아요.
- **5주차 구현**: 광고 자리와 켜고 끄는 설정을 넣어요. 기본값은 꺼져 있고, 어드민에는 띄우지 않아요.
- **출시 시**: 광고는 꺼둔 채로 출시해요.
- **광고 네트워크**: 카카오 애드핏을 먼저 신청하고 구글 애드센스를 함께 신청해요. 심사가 통과하면 설정으로 켜요.

> ⚠️ 만드는 사람 화면은 방문이 적어서 초기 광고 수익은 호스팅비에도 못 미칠 가능성이 커요(추정). 나중에 유료화하게 되면 광고 제거를 첫 유료 상품으로 검토해요.

## 7. 기술 구조

| 항목 | 내용 |
|---|---|
| 프론트 | Next.js와 TypeScript |
| 백엔드 | Supabase (DB, 로그인, 접근 권한) |
| 이미지 저장 | Cloudflare R2 |
| 호스팅 | Vercel 또는 Cloudflare Pages (1주차에 결정) |
| 라우트 구분 | 하객 페이지 `/i/*`, 제작자 화면 `/dashboard`, `/edit` |
| 초대장 페이지 | 정적으로 만들어 CDN으로 제공, DB가 멈춰도 초대장 내용은 보임 (응답 제출은 제외) |
| 비회원 작성 | Supabase 익명 로그인으로 시작, 발행 시 카카오 계정 연결(linkIdentity) |
| 공유 | 카카오 공유 SDK |
| 공용 RSVP | 같은 기기의 중복 응답은 localStorage로 막아요 |
| 이미지 | 업로드할 때 800, 1200, 1600px WebP와 썸네일을 미리 만듦 |
| 폰트 | 필요한 글자만 나눠 받고, 제목 폰트만 미리 불러와요 |
| 비용·보관 | 사진 수와 크기 제한, 행사 30일 후 사진과 하객 정보 삭제, 삭제 전 카카오 계정 이메일로만 알림, 예산 알림과 지출 상한 |
| 남용 방지 | Turnstile은 공용 RSVP 링크에만 적용, 요청 횟수 제한, 추측하기 어려운 링크 토큰 |
| 성능 목표 | 저사양 안드로이드 카톡 인앱에서 첫 화면 약 2.5초 이내 (목표치) |

## 8. 6주 일정

| 주차 | 작업 |
|---|---|
| 1주차 | 프로젝트 세팅, 호스팅(Vercel·Cloudflare Pages) 결정, 폰트와 색 테마 확정, 청첩장 템플릿 뼈대 |
| 2주차 | 만들기 화면, 비회원 초안 저장, 사진 업로드와 크롭, 크기별 변환과 색감 필터 |
| 3주차 | 공개 초대장 페이지, 갤러리, 카톡 미리보기, 스크롤 등장, 흐린 미리보기, 하단 바로가기 |
| 4주차 | 받는 사람별 링크, RSVP 집계, 미응답자 목록, 호스트 관리 화면, 카카오 로그인과 발행 흐름(비회원 초안, 로그인, 계정 연결, 고유 URL 발급) |
| 5주차 | 봉투 오프닝, 광고 자리와 켜고 끄기(꺼둠), 남용 방지, 예산 알림 |
| 6주차 | 카톡 인앱, iOS Safari, 저사양 안드로이드 실기기 점검, 약관, 베타, 출시 |

> 2주차는 업로드할 때 크기별 이미지를 만들면서 색감 필터를 함께 적용하기 때문에 일정이 빡빡해요.

일정이 밀리면 광고 코드를 출시 직후로 옮겨 이틀 정도 여유를 만들어요. 6주차 점검 기간은 줄이지 않아요. 개발이 막히지 않으려면 1주차 안에 폰트와 색, 사진 크롭 비율, 모션 속도와 길이 기준이 정해져야 해요.

## 9. 수용 기준

출시 전에 아래를 만족하는지 확인해요.

- 커버에서 스크롤 없이 날짜와 예식장이 보여요.
- 하단 바에서 계좌 복사까지 2탭 이내예요.
- 두 번째 방문부터는 봉투가 나오지 않아요.
- 기기에서 모션 줄이기를 켜면 봉투 오프닝과 스크롤 등장이 생략돼요.
- 하객 페이지에는 광고 스크립트가 없어요.
- RSVP 동행 인원은 최대 10명까지 입력할 수 있어요.
- RSVP 마감일 전까지 하객이 응답을 수정할 수 있어요.
- 돌아가신 혼주로 표기한 분에게는 연락하기 버튼이 보이지 않아요.
- 발행하려면 신랑·신부 이름, 날짜, 시간, 예식장, 주소, 대표 사진 1장이 모두 있어야 해요.
- RSVP 마감 기본값은 예식 전날 23:59이고, 마감 없음 옵션은 없어요.
- 공용 초대장 링크와 공용 RSVP 링크가 서로 다른 URL이에요.
- 고인 표기 방식은 사람마다 따로 고를 수 있고, 고인으로 표기한 분의 연락하기 버튼은 숨겨져요.
- 행사 30일 후 자동 삭제 전에 카카오 계정 이메일로만 호스트에게 미리 알려요. 대시보드 알림은 하지 않아요.

## 10. 출시 후 순서

1. 광고 네트워크 심사 신청(신청할 수 있게 되는 대로)과 통과 후 켜기
2. 방명록 (텍스트만)
3. 네이버 로그인
4. 두 번째 템플릿·색 테마 추가와 다른 행사 종류
5. 신랑측·신부측 인원 집계와 식장 전달용 요약
6. 당일 모드, 그룹 링크

## 11. 확인이 필요한 것

- **폰트 라이선스**: 웹 사용과 상업 이용이 가능한 한글 폰트인지
- **광고 심사 조건**: 로그인 뒤 화면과 콘텐츠가 적은 화면에 광고를 넣어도 되는지, 맞춤형 광고 동의가 필요한지
- **개인정보처리방침**: 광고 사업자와 쿠키 관련 조항
- **다크모드 강제 반전**: 안드로이드 카톡 인앱에서 막을 수 있는지 실기기로 확인
- **경쟁 서비스 조사**: 봉투 연출과 에디토리얼 톤이 기존 서비스보다 실제로 돋보이는지
- **카톡 미리보기 갱신**: 발행 후 수정 시 카톡 미리보기 이미지를 어떻게 갱신할지
