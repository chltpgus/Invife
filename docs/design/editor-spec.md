## 1. 원칙

1. **하객 화면이 주인공.** 제작 UI는 무채색(잉크·종이)으로 두고, 색은 미리보기 속 초대장 테마 색 하나만 보이게 함 → `color.app`(무채색) 사용, 테마 accent는 미리보기와 테마 선택에만.
2. **바꿀 수 있는 것은 색 테마·사진·문구뿐** [기획안 3장]. 폰트·레이아웃·섹션 순서 편집 UI 없음.
3. **입력 = 하객 화면 한 블록.** 모든 입력 필드는 하객 화면의 특정 요소에 1:1로 대응하고, 비워 두면 하객 화면에서 어떻게 되는지 필드 아래에 바로 알려 줌(「비워 두면 이 줄은 초대장에 보이지 않아요」).
4. **언제든 멈춰도 안전.** 자동 저장, 로그인 없이 시작 [기획안 5장], 발행 직전에만 카카오 로그인.
5. **광고** [기획안 6장]: 어드민이 아니면 화면당 배너 1개, **내 초대장 목록 · 템플릿(테마) 선택 · 발행 완료 화면에만**. 편집 중 화면, 미리보기, 공유 버튼 근처, 로그인, 하객 명단·계좌번호가 보이는 화면에는 없음. 5주차에 자리 + 켜고 끄기 구현, **출시 시 꺼 둠**. 하객 화면(`/i/*`)은 CSP로 차단.
6. 라이트 전용(제작 화면도 동일) [제안 — 기획안은 「화면 모드: 라이트 고정」을 전체 원칙으로 둠].

## 4. 진입 · 로그인 흐름 [기획안 5·7장]

```
/ 시작 → 「무료로 만들기」 → (Supabase 익명 로그인, 화면 없음) → /new 테마 선택 → 기본 정보 3개 → /edit/[id]
   └ 「이미 만든 청첩장 보기」 → 카카오 로그인 → /dashboard
/edit … 「발행하기」 → 필수값 점검 → (익명이면) 카카오 로그인 시트 → linkIdentity → 고유 URL 발급 → /published
```

### 4.1 시작 화면 `/` [제안 — 기획안에 화면 정의 없음]
- 모바일: 로고(Invife 명조 워드마크) · 한 줄「누가 만들어도 잡지 화보처럼」 · 샘플 초대장 미리보기(테마 3종 커버 썸네일, 가로 스크롤) · 주 버튼「무료로 만들기」 · 텍스트 버튼「이미 만든 청첩장 보기」 · 하단 caption「로그인 없이 시작하고, 발행할 때 카카오로 저장해요」.
- 데스크톱: 왼쪽 문구·버튼, 오른쪽 폰 프레임 샘플.
- 이 기기에 익명 초안이 있으면 「만들던 청첩장 이어서 하기」 카드를 맨 위에.
- 광고 없음 [제안]. 소개·가이드 페이지 겸용 여부는 Q1.

### 4.2 익명 세션
- 「무료로 만들기」 탭 시 `signInAnonymously` → 실패 시 인라인 오류「잠시 후 다시 시도해 주세요」 + 다시 시도.
- 익명 상태 배너(편집 화면 상단, info, 닫기 가능): 「아직 이 브라우저에만 저장돼요. 발행할 때 카카오로 연결하면 어디서든 열 수 있어요.」
- 익명 초안 보관 기간은 기획안 11장 「확인 필요」 → 배너 문구에 기간 미표기 [미정 Q2].
- 카카오 인앱 브라우저에서 시작한 경우 쿠키·저장소가 외부 브라우저와 분리됨 → 배너에 「다른 브라우저에서는 보이지 않아요」 포함 [제안, Q3].

### 4.3 카카오 로그인 (발행 직전 · 대시보드 진입)
- 버튼: 카카오 공식 디자인 가이드 준수 — 컨테이너 `#FEE500`, 공식 말풍선 심볼(#000, **공식 리소스 사용, 직접 그리지 않음**), 레이블「카카오 로그인」 `rgba(0,0,0,.85)`, radius 12, 높이 52, 폭 100%(최대 360). (developers.kakao.com 카카오 로그인 디자인 가이드, 2026-11-16 확인)
- 발행 시 시트(모바일 바텀시트 / 데스크톱 다이얼로그 480): 제목「발행하려면 카카오로 로그인해 주세요」 · 본문「지금까지 만든 내용은 그대로 카카오 계정에 저장돼요」 · 카카오 버튼 · 「나중에 할게요」.
- 상태: 로딩(버튼 스피너, 카카오로 리다이렉트) · 취소(돌아오면 시트 유지, 토스트 없음) · 실패「로그인하지 못했어요. 다시 시도해 주세요」 · **이미 가입된 카카오 계정** [세현 Q4]: 다이얼로그「이 카카오 계정은 이미 Invife에 가입돼 있어요. 이 초안을 그 계정으로 옮길까요?」 — 「옮기기」/「취소」.
- 로그인 정책(익명 로그인 + linkIdentity)은 기획안 11장 「구현 전 공식 문서로 재확인」.

## 5. 템플릿(테마) 선택 `/new` [기획안: 템플릿 1종 · 색 테마 3개]

- 제목「색을 골라 주세요」 + caption「나중에 언제든 바꿀 수 있어요」.
- 테마 카드 3개: 각 카드 = 실제 커버 축소 렌더(샘플 사진·이름, 4:5) + 이름(Ivory · Burgundy / Sage · Forest / Mist · Navy) + 색 칩 3개(bg·text·accent). 모바일 1열(카드 폭 100%, 높이 약 220, 가로형: 왼쪽 미니 커버 + 오른쪽 이름·칩) / 데스크톱 3열.
- 선택 = `2px app.text` 테두리 + check-circle, `role="radiogroup"`, 카드 = `radio`. 기본 선택 Ivory.
- 이어서 **기본 정보 3개**(같은 화면 아래 또는 다음 단계) [제안]: 신랑 이름 · 신부 이름 · 예식 날짜와 시간 → 「만들기 시작」. 이 3개만 받고 바로 편집 화면으로(나머지는 편집 화면에서). 건너뛰기 가능(빈 값이면 샘플 텍스트 미리보기).
- 광고: 화면당 1개 가능 — 테마 카드 목록 **아래**, 「만들기 시작」 버튼과 32px 이상 떨어진 위치, 라벨「광고」 명시 [제안]. 출시 시 꺼 둠.
- 편집 화면에서 테마 변경: 상단 「테마」 칩(palette 아이콘) → 같은 3카드 시트, 선택 즉시 미리보기 반영.

## 6. 편집 화면 `/edit/[id]` — **[권장] 단일 편집 화면 + 실시간 미리보기**

**왜 단계형(위저드)이 아니라 단일 편집기인가**
- 기획안은 「만들기 화면」 하나(2주차)와 미리보기, 발행 후에도 「시간, 장소, 계좌를 고칠 수 있다」를 전제 → 처음 만들기와 고치기가 같은 화면이면 구현·학습 비용이 한 번.
- 바꿀 수 있는 것이 문구·사진·테마뿐이라 단계를 나눌 만큼 분기가 없음.
- 대신 처음 쓰는 사람을 위해: 섹션 목록에 **완료 표시**(필수값 채움 여부)와 「다음 섹션」 버튼을 두어 위저드처럼 위에서 아래로 따라갈 수 있게 함.

### 6.1 레이아웃
- **모바일**: 상단 바 → (익명 배너) → 테마 칩 → **섹션 아코디언 목록**(하객 화면 순서 1–9 + 사진 + RSVP 설정). 한 번에 하나만 펼침. 각 헤더 = 섹션명(appSection) + 요약 1줄(appCaption, 예「김민준 · 이서연 · 2027.5.15 오후 1시」) + 상태 배지(완료 check-circle / 필수 미입력 「필수」 / 선택「비어 있음 · 초대장에서 숨겨져요」) + chevron. 하단 액션 바(미리보기 · 발행).
- **desktop**: 왼쪽 폼 520(같은 아코디언, 또는 wide에서 왼쪽 섹션 내비 200 + 폼에 섹션 전부 펼친 스크롤) · 오른쪽 미리보기 폰 프레임(390×844, 남은 높이에 맞춰 `transform: scale()` 축소, 최소 0.6). **폼 섹션에 포커스하면 미리보기가 해당 섹션으로 스크롤**하고 해당 영역에 2px app.focus 외곽선 1초 표시 [제안].
- 미리보기 프레임 위: 크기 토글 `390×844` / `360×640`(phone-frame 아이콘), 「봉투 다시 보기」(refresh), 「크게 보기」(전체 미리보기 9장).

| 관계 표기 | 「아들」/「딸」 기본, 자유 입력 0–6자(장남·차녀 등) | 기본값 |
- 양쪽 부모 이름이 모두 비면 그 줄 숨김, 양측 모두 비면 **혼주 성함 블록 숨김**.
- **고인 표기 방식 [세현 Q8]**: 아버지·어머니 각각 고인 체크 시, 그 사람 아래에 라디오 「고인 표기」 `故 {이름}`(한자) / `고 {이름}`(한글). 사람마다 따로 고르고, 선택 전이면 발행 오류「{관계} 고인 표기 방식을 골라 주세요」.
- 고인 체크 시 caption「고인으로 표시하면 연락하기에서 이 분의 연락처는 보이지 않아요」, 그리고 ④의 해당 전화번호 필드를 **비활성 + 값 숨김**(값은 지우지 않고 보관 → 체크 해제 시 복원) [제안].

#### ④ 연락하기 → 하객 7.3
| 필드 | 형식 | 비우면 |
|---|---|---|
| 신랑 / 신부 / 신랑 아버지 / 신랑 어머니 / 신부 아버지 / 신부 어머니 전화번호 | `010-0000-0000` 자동 하이픈, `inputmode="tel"`, 휴대폰·일반번호 허용 | 그 사람 행 숨김 |
- 각 행 라벨에 ③의 이름을 자동 표시(이름 없으면 「신랑 아버지」).
- 고인 → 필드 비활성, caption「고인으로 표시돼 연락하기에서 숨겨져요」 [세현].
- 전원 비면 **연락하기 블록 숨김**. 그룹 전원 비면 그 그룹 숨김.
- 개인정보 caption: 「입력한 번호는 초대장을 받은 누구나 볼 수 있어요」 [제안, 필수 고지 문구 여부는 Q9].

#### ⑤ 일시 상세와 달력 → 하객 7.4
- 입력 없음(① 날짜·시간 사용). 섹션 헤더에 「커버의 날짜로 자동으로 만들어져요」.

#### ⑥ 갤러리 → 하객 7.5 — 사진은 8장 「사진 업로드·초점」
- 요약: 「사진 7 / 10」, 썸네일 줄, 「사진 편집」 버튼. 0장이면 **갤러리 섹션 숨김**(커버도 사진 없는 레이아웃).

#### ⑦ 오시는 길 → 하객 7.6
| 필드 | 형식 | 필수 | 비우면 |
|---|---|---|---|
| 주소 | 「주소 검색」 버튼 → 주소 검색 시트(도로명) → 좌표 자동 변환 | 필수 [제안] | — |
| 상세 주소 | 0–40자(층·호) | 선택 | 생략 |
| 지도 핀 확인 | 검색 후 작은 지도 + 「핀 위치가 맞나요?」 + 드래그로 미세 조정 [제안] | — | 좌표 없음 → 지도·지도앱 버튼 숨김, 주소 복사만 |
| 주차 | textarea 0–100자 | 선택 | 그 항목 숨김 |
| 지하철 | 0–100자 | 선택 | 숨김 |
| 버스 | 0–100자 | 선택 | 숨김 |
| 기타 안내 | 0–100자 [제안] | 선택 | 숨김 |
- 주소 검색 제공사: 지도 제공사 결정(하객 스펙 Q12, 카카오 권장)과 같이 감 — 카카오 우편번호 서비스 + 카카오 로컬 API(좌표 변환) [권장, 미확인 사항: 한도·약관].
- 교통 4개 모두 비면 교통 블록 숨김.

#### ⑧ 마음 전하실 곳(계좌) → 하객 7.7
신랑측 / 신부측 탭(또는 두 카드), 각 최대 3개 [제안 — 기획안에 개수 없음, Q10]:
| 필드 | 형식 |
|---|---|
| 관계 | 선택: 본인 / 아버지 / 어머니 / 직접 입력 |
| 예금주 | 2–20자 |
| 은행 | 선택 목록(주요 은행·증권사, 검색 가능 콤보박스) |
| 계좌번호 | 숫자와 하이픈만, 8–20자리, `inputmode="numeric"` |
- 「계좌 추가」(plus) · 행 삭제(trash, 확인 없이 삭제 + 토스트 「삭제했어요 · 되돌리기」 5초) · 순서 이동(grip 드래그 + 위/아래 버튼).
- 한쪽 0개 → 하객 화면에서 그 아코디언 숨김, 양쪽 0개 → **섹션 + 바로가기 항목 숨김**. 안내 문구 textarea 0–80자(비우면 생략).

- 화면에 계좌번호가 보이므로 이 섹션이 펼쳐진 편집 화면은 광고 없음(편집 화면 전체가 원래 광고 없음).

#### ⑨ 참석 여부(RSVP) 설정 → 하객 7.8
| 설정 | UI | 기본값 |
|---|---|---|
| 응답 마감 [세현 Q11] | 날짜 + 시간 선택, 「예식 전날 밤 12시」 프리셋 버튼 | **예식 전날 23:59 (KST)**. 마감 없음·RSVP 끄기 없음 |
| 응답 수정 허용 | 안내만: 「하객은 마감 전까지 응답을 고칠 수 있어요」 [세현] (설정 아님) | — |
| 동행 인원 상한 | 안내만: 「본인 제외 최대 10명까지 받아요」 [세현] (설정 아님) | 10 고정 |
| 공용 RSVP 링크 | 발행 후 링크 + 복사 버튼, 발행 전엔 「발행하면 만들어져요」 | — |
- 마감 검증: 지금 이후, 예식 일시 이전(또는 당일 예식 전까지) → 오류「마감은 지금보다 뒤, 예식 시간보다 앞이어야 해요」.
- RSVP 자체를 끄는 옵션은 기획안에 없음 → 제공하지 않음 [미정 Q12].
- 마감 후 하객 화면 = 하객 스펙 7.8 Closed.

### 6.3 섹션 완료 표시 규칙
- 완료(check-circle, success): 그 섹션의 필수값 모두 유효.
- 필수(배지 「필수」, warning): 필수값 누락.
- 오류(alert, error): 형식 오류가 있는 필드 존재.
- 비어 있음(caption): 선택 섹션 전체 비움 → 「초대장에서 숨겨져요」.

## 7. 자동 저장

- **필드 변경 후 800ms 디바운스**(입력 중 최대 5초마다 강제 저장), **blur 시 즉시**, 사진 작업은 완료 시점마다. (`motion.editor.autosaveDebounceMs`)
- 저장 단위: 초대장 초안 JSON 전체 PATCH(낙관적 업데이트). 저장 성공 응답의 `updated_at`을 보관.
- 상태 표시(상단 바, `aria-live="polite"`, 아이콘 + appCaption):
  | 상태 | 표시 |
  |---|---|
  | 저장 중 | spinner(정지형 가능) + 「저장 중…」 |
  | 저장됨 | cloud-check + 「저장됨」 → 2초 후 「방금 저장」/「3분 전 저장」 |
  | 오프라인 | cloud-off + 「오프라인 · 연결되면 저장해요」 (변경은 localStorage 큐에 보관) |
  | 실패 | cloud-off(error) + 「저장하지 못했어요」 + 「다시 시도」 링크. 3회 연속 실패 시 상단 배너 |
- 다른 탭/기기에서 더 최신 버전이 있으면(서버 `updated_at`이 더 큼): 배너 「다른 곳에서 수정된 내용이 있어요」 + 「최신 내용 불러오기」 / 「이 화면 내용으로 덮어쓰기」 [제안].
- 페이지 이탈 시 미저장 변경이 있으면 `beforeunload` 경고.
- **발행된 초대장**: 자동 저장은 초안에만 → 하객 화면은 「변경 사항 반영」을 눌러야 바뀜(11장) [권장].
- 미리보기 반영: 입력 300ms 디바운스로 즉시(저장 성공과 무관).

## 8. 사진 업로드 · 초점 · 필터 (하객 스펙 11장 규칙)

### 8.1 사진 편집 화면(모바일 전체 화면 / 데스크톱 폼 영역 + 미리보기 유지)
- 상단: 「사진 7 / 10」 + caption「첫 번째 사진이 커버와 갤러리 대표가 돼요」.
- 그리드: 모바일 3열 정사각 / 데스크톱 4열. 첫 칸에 「커버」 배지. 마지막 칸 = 추가 타일(image-plus, 「사진 추가」, 10장이면 숨김).
- 각 타일 메뉴(more-vertical, 44): 초점 지정 · 맨 앞으로(커버로) · 삭제.
- 순서 변경: 길게 눌러 드래그(grip) + 접근성용 「앞으로/뒤로」 메뉴 항목. 드래그 중 타일 `shadow.dialog` + scale 1.02(움직임 줄이기면 없음).
- 하단: **색감 필터** 세그먼트 `원본 · 따뜻하게 · 흑백` — **10장 일괄 적용** [기획안 「10장의 톤을 맞춰요」], 선택 즉시 그리드·미리보기 반영.

### 8.2 업로드
- 입력: `<input type="file" accept="image/jpeg,image/png,image/heic,image/heif,image/webp" multiple>`, 데스크톱은 드래그 앤 드롭 영역(점선 `app.border`, 「여기에 사진을 끌어다 놓으세요」).
- 남은 장 수보다 많이 고르면 앞에서부터 남은 수만 + 토스트「사진은 10장까지 올릴 수 있어요. 3장은 빠졌어요」.
- 처리: HEIC 변환 → EXIF 회전 반영·위치정보 제거 → 긴 변 2400px 리사이즈 → 업로드(동시 3장) → 서버가 800/1200/1600 WebP + 썸네일 + LQIP 생성.
- 타일 상태:
  | 상태 | 표시 |
  |---|---|
  | 대기 | 로컬 미리보기 흐리게 + 「대기 중」 |
  | 업로드 중 | 하단 진행 바(2px, app.text) + 「42%」, 취소(close) |
  | 처리 중 | 「변환 중…」 스켈레톤 |
  | 완료 | 사진 |
  | 저화질 경고 | 짧은 변 < 800px → 좌상단 info 배지, 탭하면「화질이 낮아 흐리게 보일 수 있어요」 (차단 아님) |
  | 실패 | image-off + 「올리지 못했어요」 + 「다시 시도」 / 「삭제」 |
- 오류 문구:
  - 형식: 「JPG, PNG, HEIC, WebP 사진만 올릴 수 있어요」
  - 용량: 「20MB보다 큰 사진은 올릴 수 없어요」 (20MB는 [제안], 하객 스펙 11장)
  - 장 수: 「사진은 10장까지 올릴 수 있어요」
  - 네트워크: 「연결이 불안정해요. 다시 시도해 주세요」
  - 한도(비용·남용 제한): 「잠시 후 다시 시도해 주세요」

### 8.3 초점(얼굴 위치) 지정 [기획안 「얼굴 위치를 탭해 두면…」]
- 화면: 원본 사진 전체(contain) 위를 **한 번 탭** → crosshair 마커(지름 32, 흰 테두리 2 + 그림자로 어떤 사진에서도 보임). 다시 탭하면 이동, 드래그 가능. 키보드: 방향키 1% 이동, Shift+방향키 10%.
- 아래에 **비율 미리보기 동시 표시**: 커버 4:5 · 썸네일 1:1 · 카톡 공유 2:1 (사진이 첫 장이면 커버·공유, 아니면 썸네일·뷰어) — 실제 `object-position` 결과로 렌더.
- 버튼: 「가운데로 되돌리기」 · 「완료」. 기본 초점 = (0.5, 0.4) [제안 — 인물 사진은 위쪽에 얼굴이 많음].
- 자유 크롭·확대·회전 UI 없음(원본 보관, 초점만 저장) — 기획안 「자유도를 줄이고 디테일 고정」과 일치.
- 접근성: 사진 영역 `role="application"` + 설명 「사진을 탭하거나 방향키로 얼굴 위치를 지정하세요. 현재 가로 48%, 세로 32%」(aria-live).

## 9. 미리보기

- **실시간 미리보기**(데스크톱 오른쪽 패널, 태블릿 오버레이): 하객 화면 컴포넌트를 그대로 렌더(별도 구현 금지), 폰 프레임 390×844(radius 40, `1px app.line`, `shadow.previewFrame`), 토글로 360×640. 봉투는 기본 생략, 「봉투 다시 보기」로 재생.
- **전체 미리보기**(모바일 「미리보기」 / 데스크톱 「크게 보기」): 모바일은 실제 화면 전체에 하객 화면 + 상단 얇은 바(「미리보기」 라벨 + 닫기 + 봉투 다시 보기), 첫 진입 시 봉투부터. 데스크톱은 폰 프레임을 화면 중앙에 1:1 크기.
- 미리보기에서는 RSVP 제출·복사·전화가 실제로 동작하지 않음 → 누르면 토스트「미리보기에서는 보내지지 않아요」.
- 빈 필수값은 미리보기에서 회색 샘플 텍스트로 표시(예「신랑 이름」) [제안]. 하객 화면에는 절대 샘플 텍스트가 나가지 않음(발행 검증).
- 광고 없음 [기획안].

## 10. 발행 · 공유

### 10.1 발행하기
1. 「발행하기」 → **발행 점검 시트**: 필수값 체크리스트(누락 항목은 탭하면 해당 필드로 이동·포커스). 누락 있으면 주 버튼 비활성 + 「필수 항목 2개를 채워 주세요」.
2. 선택 항목 요약(「비어 있어 숨겨지는 섹션: 인사말, 마음 전하실 곳」) — 의도 확인용 [제안].
3. 익명이면 카카오 로그인 시트(4.3) → linkIdentity.
4. 고유 URL 발급 + 정적 페이지·OG 이미지 생성: 로딩 화면「청첩장을 만들고 있어요」(최대 수 초, 스피너 + 단계 텍스트).
5. 실패: 「발행하지 못했어요. 입력한 내용은 저장돼 있어요」 + 다시 시도.
- URL 형식: `/i/{추측 어려운 토큰}` [기획안 「추측하기 어려운 링크 토큰」] — 사람이 읽는 슬러그(예 `/i/minjun-seoyeon`) 허용 여부는 [미정 Q13].

### 10.2 발행 완료 · 공유 화면
- 상단: check-circle + 「청첩장이 완성됐어요」(appTitle) + 초대장 링크 표시(말줄임) .
- **카톡 공유 미리보기 카드**: 실제 OG 이미지(2:1) + og:title + og:description을 카카오 말풍선 모양으로 보여 줌 — 「카톡에서 이렇게 보여요」(하객 스펙 10.1 레이아웃).
- 공유 버튼(모바일 세로 스택 / 데스크톱 가로):
  - **카카오톡으로 보내기**: `#FEE500` 배경, 공식 카카오톡 심볼, 레이블 검정 85%, radius 12, 높이 52 — 카카오 공유 SDK `feed`(imageWidth 800 / imageHeight 400). 공유 버튼 디자인 세부 규정은 로그인 가이드를 준용 [미확인].

## 11. 발행 후 수정 · 발행 취소 · 삭제

### 11.1 발행 후 수정 [기획안 5장: 시간·장소·계좌 수정, 링크 유지]
- 같은 편집 화면. 상단에 「발행됨」 배지 + 링크.
- 편집 내용은 초안에 자동 저장되고, **「변경 사항 반영」**을 눌러야 하객 화면에 반영 [권장 — 정적 페이지 재생성·OG 재생성 타이밍을 명확히 하고, 실수로 반쯤 고친 내용이 하객에게 보이는 것을 방지]. 반영 전 변경이 있으면 상단 바 버튼 활성 + 점(●) 표시, 이탈 시 경고.
- 반영 확인 시트: 변경 요약(「예식 시간: 오후 1시 → 오후 1시 30분」, 「계좌 1개 추가」) + 「반영하기」.
- 기획안은 「시간, 장소, 계좌」를 예시로 듦 → **모든 필드 수정 가능**으로 해석 [충돌 가능, Q17].
- 날짜·시간·장소가 바뀌면: 이미 응답한 하객에게 알릴 방법이 기획안에 없음 → 반영 시트에 caption「이미 응답한 하객에게는 따로 알려 주세요」 [Q18].
- **카톡 미리보기 갱신** [기획안 11장 확인 필요]: OG 이미지 URL에 버전 쿼리(`?v={updated_at}`)를 붙여 SDK 공유는 새 이미지를 쓰게 함. 이미 보낸 말풍선·URL 스크랩 캐시는 카카오 쪽 캐시라 즉시 바뀌지 않을 수 있음 → 반영 시트 caption「이미 보낸 카톡 미리보기는 바로 바뀌지 않을 수 있어요」 [미확인, Q19].
- RSVP 마감을 앞당겨 이미 지난 시점으로 바꾸면 즉시 마감 → 확인「저장하면 바로 응답이 마감돼요」.

### 11.2 발행 취소
- 설정 화면 「발행 취소」(globe-off) → 다이얼로그: 「발행을 취소하면 링크를 연 사람에게 ‘초대장을 찾을 수 없어요’가 보여요. 응답과 사진은 남아 있고, 다시 발행하면 같은 링크로 돌아와요.」 [제안 — 같은 링크 재사용 여부 Q20] · 버튼 「발행 취소」(error 테두리 보조 버튼) / 「닫기」.

### 11.3 삭제
- 설정 화면 맨 아래 「청첩장 삭제」(trash, error 텍스트).
- 다이얼로그: 「청첩장을 삭제하면 사진, 하객 명단, 응답이 모두 지워지고 되돌릴 수 없어요.」 + 확인 입력 「삭제」 타이핑 후 버튼 활성 [제안] · 「삭제하기」(error 배경 #A3312A + 흰 글자, 대비 6.93) / 「취소」.

## 15. 접근성

- 대비: `color.appContrast` — 텍스트 모두 AA 이상, 입력 테두리 `app.border` 3.36:1 이상(비텍스트 3:1). `app.line`은 장식 전용.
- 모든 입력에 보이는 `<label>`(placeholder를 라벨로 쓰지 않음), 필수는 라벨 옆 「필수」 텍스트(색만 X).
- 오류: 필드 아래 메시지 + `aria-describedby`, 발행 점검에서 첫 오류 필드로 포커스 이동.
- 아코디언 `button[aria-expanded]`, 섹션 상태 배지는 헤더 접근명에 포함(「인사말, 비어 있음, 초대장에서 숨겨져요」).
- 드래그 정렬은 반드시 버튼/메뉴 대안 제공. 초점 지정은 키보드 대안(8.3).
- 자동 저장 상태 `aria-live="polite"`, 토스트 `role="status"`, 치명 오류 `role="alert"`.
- 다이얼로그/시트 포커스 가두기 + Esc + 닫힘 시 트리거로 복귀. 모바일 시트는 아래로 끌어 닫기 + 닫기 버튼.
- 터치 영역 ≥44, 모바일 입력 16px, rem 단위, 200% 확대 시 2분할 → 1열로 자연 전환(브레이크포인트가 CSS px 기준이므로 확대 시 tablet/mobile 레이아웃이 됨).
- 미리보기 iframe에는 `title="초대장 미리보기"`, 미리보기 내부는 하객 접근성 규칙 그대로.
- 움직임 줄이기: 하객과 동일 규칙(`motion.editor.reducedMotion`), 스켈레톤 펄스 정지.
